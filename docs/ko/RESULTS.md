# 결과 다루기

결과는 문서 안의 결과 탭에 렌더링됩니다. 각 테이블이나 컬렉션은 드라이버가 해당 객체에 선언한 뷰로 열리며, 선언된 다른 뷰도 함께 제공합니다:

- 관계형 테이블과 쿼리 결과에는 **테이블 뷰**.
- 문서 컬렉션(예: MongoDB, DynamoDB)에는 **트리 뷰**. 같은 페이지를 **테이블**과 **JSON** 뷰로도 볼 수 있습니다([문서 컬렉션](DOCUMENTS.md) 참고).
- JSON 열이 있는 테이블에는 **테이블 뷰**와 같은 행의 **트리** 뷰([테이블의 JSON 열](DOCUMENTS.md#테이블의-json-열) 참고).
- InfluxDB measurement나 TimescaleDB hypertable 같은 시계열에는 행을 차트로 그릴 수 있을 때 **그리드 위의 차트**([시계열 테이블과 컬렉션](CHARTS.md#시계열-테이블과-컬렉션) 참고).
- Redis에는 **키-값 뷰**([키-값 브라우저](../KEY_VALUE.md) 참고).

드라이버가 해당 표현을 선언하면 이벤트 스트림 방식의 컨테이너는 이벤트 스트림으로 열립니다.

벡터 열이 있는 테이블은 선택한 행과 가장 [유사한 행](#유사한-행)도 보여 줍니다.

## 데이터 그리드 탐색

결과 패널에 포커스가 있을 때:

- `j`/`k` (또는 `Down`/`Up`) — 행 사이를 이동합니다.
- `h`/`l` (또는 `Left`/`Right`) — 열 사이를 이동합니다.
- `g`/`Shift+g` (또는 `Home`/`End`) — 첫 / 마지막 행.
- `Ctrl+d`/`Ctrl+u` (또는 `PageDown`/`PageUp`) — 행을 페이지 단위로 이동합니다.
- `[` / `]` — 이전 / 다음 결과 페이지 (페이지 나누기).
- `f`는 도구 모음으로, `/`는 검색/필터로 포커스를 옮깁니다.
- `z`는 패널 접기를 토글합니다.
- `m` (또는 `Shift+F10`)은 행/셀 상황에 맞는 메뉴를 엽니다.
- `=`는 선택한 셀의 값을 테이블의 `WHERE` 필터에 추가합니다([셀로 필터링](#셀로-필터링) 참조).

셀의 상황에 맞는 메뉴(`m`, `Shift+F10` 또는 오른쪽 클릭)는 화면에 들어가도록 묶여 있습니다. 맨 위에는 **복사**, **다른 형식으로 복사 ▸**(CSV, JSON, SQL IN 목록, INSERT 문, Markdown 표, 테이블에서는 행을 쿼리로), **값 보기**, **필터에 추가**가 있습니다. 그다음 편집 항목인 **편집**, **편집기에서 편집…**, **SQL 식으로 편집…**, **붙여넣기**, **값 설정 ▸**(NULL, DEFAULT, 열이 받을 수 있는 식별자)가 옵니다. 이어서 **필터 ▸**, **정렬 ▸**, **열 ▸**(숨기기, 이동, 고정, 너비 맞춤, 열…), **행 ▸**(검사, 추가, 복제, 연결의 행 작업, 맨 끝에 따로 행 삭제)가 있고, 마지막으로 **더 보기 ▸**(SQL 생성 ▸, 이 쿼리로 차트 만들기, 유사한 행 찾기)와 **도구 모음 ▸**이 있습니다. 각 부분은 셀에 해당하는 것만 보여 주며 행마다 단축키가 그대로 표시됩니다. `Up` / `Down`으로 메뉴를 이동하고, `Enter` 또는 `Right`로 행을 실행하거나 하위 메뉴를 열며, `Left` 또는 `Escape`로 뒤로 돌아갑니다. 창의 아래쪽이나 오른쪽 가장자리 근처에서 연 메뉴는 위로 열리거나 왼쪽으로 옮겨지고, 하위 메뉴는 공간이 있는 쪽으로 열리며, 창보다 긴 메뉴는 스크롤되면서 강조된 행을 보이게 유지합니다. 열 헤더 메뉴와 내보내기 메뉴도 같은 방식으로 창 안에 맞춰집니다.

마우스로 클릭하면 셀이 선택되고, `Shift`+클릭하거나 누른 채로 드래그하면 다른 셀까지의 범위가 선택됩니다. 행 번호를 클릭하면 행 전체가 선택되고, 다른 행 번호를 `Shift`+클릭하면 그 사이의 모든 행이 선택됩니다. 셀이나 행 번호를 `Ctrl`+클릭(macOS에서는 `Cmd`+클릭)하면 선택에 추가되고, 그것만 선택되어 있으면 선택이 해제됩니다. 여러 범위를 복사하면 범위가 걸친 행과 열이 복사되며, 선택되지 않은 셀은 비어 있습니다. 추가한 범위는 복사용입니다. 삭제, 복제, 저장 등 행 작업은 커서가 있는 행에 적용되고, 오른쪽 클릭은 포인터 아래의 셀을 선택하며, 레코드 뷰에서는 `Ctrl`+클릭이 일반 클릭으로 동작합니다. 그리드 가장자리 밖으로 드래그하면 그 방향으로 스크롤되며, 포인터가 멀어질수록 빨라지고, 버튼을 놓거나 포인터가 돌아올 때까지 범위가 계속 늘어납니다.

선택 영역이 두 개 이상의 셀에 걸치면 상태 표시줄에 셀 개수와, 그중 숫자 값의 합계, 평균, 최소값, 최대값이 표시됩니다. NULL과 텍스트는 개수에는 포함되지만 계산에서는 제외되며, 상태 표시줄에 제외된 개수가 표시됩니다. 합계는 저장하지 않은 편집을 포함해 이미 불러온 행으로 계산하며, 데이터베이스를 다시 조회하지 않습니다.

## 레코드 뷰

`i`를 누르거나 결과 상태 표시줄의 Grid / Record 토글을 사용하면 활성 행이 결과 영역을 채우는 이름/값 목록으로 표시됩니다. 헤더에는 결과에서 해당 행의 위치가 표시됩니다. 필드는 그리드 셀과 정확히 같은 방식으로 편집되므로, 저장하지 않은 변경 사항, 행 저장, 되돌리기는 두 레이아웃에서 똑같이 동작합니다. `Up`/`Down`은 필드 사이를, `Left`/`Right`는 행 사이를 이동합니다. `i`를 다시 누르면 그리드로 돌아갑니다.

## 열 헤더 메뉴

열 헤더를 마우스 오른쪽 버튼으로 클릭하면 해당 열에 한정된 메뉴가 열립니다. 오름차순 또는 내림차순 정렬, 정렬 지우기, 모든 필터 연산자를 하나의 평면 목록에서 제공합니다. 헤더를 왼쪽 클릭하면 열 전체가 선택됩니다(`Shift`+클릭은 그 열까지의 모든 열을 선택하고, `Ctrl`+클릭(macOS에서는 `Cmd`+클릭)은 열을 추가하거나 제거합니다). 헤더 오른쪽 끝의 화살표를 클릭하면 정렬이 순환되며, 열이 정렬되지 않은 동안에는 흐린 위/아래 화살표가 표시됩니다. **열 헤더를 클릭하면 열 정렬**을 켜면(Settings > General > Data grid) 헤더를 일반 클릭할 때 화살표처럼 열이 정렬됩니다.

여러 열로 정렬하려면 다른 열의 화살표를 `Shift`+클릭합니다. 그 열이 다음 정렬 키(오름차순)가 되고, 다시 `Shift`+클릭하면 내림차순이 되며, 한 번 더 누르면 정렬에서 빠집니다. 화살표가 클릭을 직접 받으므로 화살표의 `Shift`+클릭은 헤더의 나머지 부분에서처럼 열 선택을 넓히지 않습니다. 키가 둘 이상이면 정렬된 각 헤더의 화살표 옆에 순서(1, 2, 3)가 표시되고, 첫 번째 키가 같은 행은 두 번째 키로 정렬되는 식입니다. 어떤 화살표든 일반 클릭하면 다시 그 열 하나로만 정렬되며, 이미 키였던 열은 원래 방향을 유지합니다. 기본 키가 여러 열인 테이블은 그 모든 열로 정렬된 채 열리므로 키 열에 처음부터 1, 2가 표시됩니다. 열 메뉴와 셀 메뉴의 **정렬 ▸**에 있는 **정렬에 추가: 열 ASC**와 **정렬에 추가: 열 DESC**도 같은 일을 하며, 이미 키인 열은 방향만 바꿉니다. **정렬 제거**는 모든 키를 없앱니다. 테이블은 모든 키를 하나의 `ORDER BY`로 데이터베이스에 보내고, 쿼리 결과는 메모리에서 정렬됩니다. 기본 순서(기본 키)를 유지하고 있는 테이블에서는 처음 추가한 키가 그 순서를 대신합니다. 기본 키로 먼저 정렬된 행에는 다른 열이 정렬할 동순위가 남지 않기 때문입니다. 정렬을 지우면 기본 순서로 돌아갑니다.
`Shift+m`을 누르면 선택한 셀의 열에 대해 같은 메뉴가 키보드로 열립니다. 메뉴의
마지막에는 보기 설정인 **열** 섹션이 있으며, 이 설정은 그리드가 열을 보여 주는
방식만 바꾸고 쿼리는 바꾸지 않습니다. **너비 맞춤**은 열을 헤더와 불러온 값에
맞추며, 긴 JSON 값 하나가 나머지 그리드를 화면 밖으로 밀어내지 않도록 최대
640픽셀까지 넓힙니다. 헤더 오른쪽 경계의 크기 조절 가장자리를 두 번 클릭해도
같습니다.

**열 숨기기**는 열을 화면에서 없애고, **열…**은 모든 열을 나열하며 표시된 열에
확인 표시를 합니다. `Enter`, `Space` 또는 클릭으로 강조된 열을 표시하거나 숨기며
목록은 열린 채로 유지되고, **모든 열 표시**는 숨긴 열을 모두 되돌리며, `Escape`는
목록을 닫습니다. **왼쪽으로 이동**과 **오른쪽으로 이동**은 열을 한 칸 옮기고, 헤더를
다른 헤더 위로 끌어다 놓으면 그 열이 그 자리로 옮겨집니다.

**열 고정**은 그리드를 가로로 스크롤하는 동안에도 틀 고정처럼 열을 행 번호 바로
옆 왼쪽 가장자리에 붙여 둡니다. 넓은 로그 테이블에서 `id`와 `created_at`을 고정하면
항상 보입니다. 고정된 열은 고정한 순서대로 그리드 맨 앞에 오며 헤더에 핀이
표시되고, **열 고정 해제**를 누르면 열이 나머지 열의 첫 번째로 다시 스크롤됩니다.
선택, 편집, 정렬, 크기 조절과 행 번호는 고정된 열에서도 똑같이 동작합니다. 왼쪽으로
이동과 오른쪽으로 이동은 고정 경계의 같은 쪽에 머물며, 헤더를 경계 너머로 끌면 그
열이 고정되거나 고정 해제됩니다. 고정된 열은 그리드 너비의 최대 3분의 2까지만 차지하므로
나머지 열에는 항상 자리가 남습니다. 좁은 그리드에서는 이 범위를 넘는 고정 열이 그리드가
다시 넓어질 때까지 다른 열과 함께 스크롤됩니다.

쿼리는 계속 모든 열을 읽습니다(테이블은 여전히 `SELECT *`를 실행합니다). 쿼리
자체에서 열을 빼려면 쿼리 빌더의 프로젝션을 사용하세요. 복사, CSV로 복사, JSON으로
복사는 화면을 따릅니다. 즉 표시된 열을 그리드가 보여 주는 순서대로 복사합니다. 행
복사, 쿼리로 복사, 내보내기는 숨긴 열을 포함한 전체 행을 결과의 원래 순서대로
사용합니다. 테이블은 연결, 데이터베이스, 스키마, 테이블별로 레이아웃을 기억하며,
테이블을 닫았다 열거나 DBFlux를 다시 시작해도 유지됩니다. 모든 열을 표시한 채
테이블의 원래 순서로 되돌리면 기억이 지워집니다. 쿼리 결과는 탭이 열려 있는 동안
레이아웃을 유지합니다. 문서 그리드는 필드 순서를 유지하며 너비 맞춤만 제공합니다.

## 값 패널

셀을 마우스 오른쪽 버튼으로 클릭하고 **값 보기**를 선택하거나 `v`를 누르면 오른쪽 검사기 레일에서 해당 셀이 열립니다. 패널은 값을 JSON, XML 또는 일반 텍스트로 표시합니다. 형식은 내용에서 감지되며 실제로 파싱에 성공할 때만 적용되고, 예쁘게 인쇄(pretty-print), 압축, 단어 줄 바꿈을 지원합니다. 여기서 편집할 수도 있습니다. **저장**은 해당 행을 바로 커밋하고, **되돌리기**는 편집을 버립니다. 패널은 그리드에서 선택하는 셀을 따라 이동하지만, 저장하지 않은 변경 사항이 있을 때는 따라가지 않습니다.

이진 셀(`bytea`, `BLOB`, `varbinary` 등)은 읽기 전용 16진수 덤프로 열립니다. 바이트가 PNG, JPEG, GIF, WebP 또는 BMP 이미지이면(열 이름이 아니라 바이트 자체로 판별합니다) 패널은 대신 그림을 패널에 맞게 축소해 보여 주고, 그 아래에 픽셀 크기, 형식, 바이트 크기를 표시합니다. **16진수**는 16진수 덤프로, **이미지**는 그림으로 전환합니다. **다른 이름으로 이미지 저장…**은 저장된 바이트를 파일로 쓰고, **이미지 복사**는 이미지를 클립보드에 넣습니다. 둘 다 그리드의 상황에 맞는 메뉴(`m`)의 도구 모음 항목에도 있습니다. 이미지를 base64로 담은 텍스트 셀도(그대로이든 `data:image/...;base64,` URI이든) 같은 방식으로 그림으로 열리며, **텍스트**로 텍스트에 돌아갑니다.

32MB 또는 32메가픽셀을 넘는 이미지는 디코딩하지 않으며, 크기 제한으로 잘린 값처럼 이미지보다 먼저 끝나는 값도 디코딩하지 않습니다. 이때 패널은 16진수 덤프 위에 이유를 표시합니다. 애니메이션 이미지는 첫 프레임만 보여 주고, SVG는 그리지 않습니다. 큰 값의 16진수 덤프는 처음 64KB까지만 표시합니다.

## 행 인스펙터

`Ctrl+Space`를 누르거나 행을 마우스 오른쪽 버튼으로 클릭하고 **행 검사**를 선택하면 선택한 행이 오른쪽 검사기 레일에서 열립니다. 행의 모든 열과 값을 나열하고 기본 키와 외래 키 열을 표시합니다. 그리드에서 이동할 때 인스펙터는 선택한 행을 따라가고, 헤더의 고정 버튼으로 현재 행에 고정할 수 있습니다. 하단의 **편집**, **복제**, **삭제**는 결과를 편집할 수 있을 때 검사 중인 행에 적용됩니다. `Ctrl+Space`를 다시 누르거나 닫기 버튼으로 인스펙터를 끌 수 있습니다.

**참조** 아래에서 인스펙터는 행의 외래 키를 양방향으로 나열합니다:

- **나가는 참조(Outgoing)** — 이 행의 단일 열 외래 키가 다른 테이블을 가리킵니다. 항목은 해당 테이블과 가리키는 행을 표시하는데, 해석되면 참조된 행의 읽을 수 있는 레이블("María López · #8")로, 그 전까지는 키 값으로 표시합니다. 항목을 클릭하면 참조된 테이블이 그 행에서 열립니다. DBFlux는 해당 테이블의 기존 탭을 재사용하고(없으면 새로 열고) 필터를 기본 키 동등 조건으로 바꿔 참조된 행이 보이도록 합니다.
- **들어오는 참조(Incoming)** — 다른 테이블의 외래 키가 이 행을 가리킵니다. 각 항목은 테이블 이름과 그 테이블의 몇 행이 이 행을 참조하는지 표시하며, 개수는 백그라운드에서 로드됩니다. 이 항목은 참고용입니다.

그리드의 외래 키 셀도 id 옆에 같은 참조된 행 레이블을 표시할 수 있습니다. [설정](SETTINGS.md)에서 **외래 키 셀에 참조된 행의 레이블 표시**를 켜면 됩니다. 행 인스펙터는 이 설정과 무관하게 항상 참조를 해석합니다.

## 결과 필터링

데이터 그리드 도구 모음에는 입력한 조건으로 쿼리를 다시 실행하는 `WHERE` 필터 입력 필드가 있습니다. SQL 연결에서는 두 가지 스타일을 지원합니다:

- **Raw `WHERE`** — 일반 조건을 입력합니다(예: `status = 'active'`). 기본 동작입니다.
- **관계형(ORM 스타일) 경로** — 외래 키를 따라가는 점 표기 경로를 입력합니다. 예: `created_by.email LIKE '%@acme.com'` 또는 `created_by.organization.name = 'Acme'`. DBFlux는 테이블의 외래 키 메타데이터를 기준으로 경로를 해석하고 참조된 테이블까지 조인을 대신 수행하므로 JOIN을 직접 작성할 필요가 없습니다.

관계형 필터가 해석되면 추가된 조인 수를 칩으로 표시합니다. 세그먼트가 모호하거나 해석할 수 없으면 인라인 오류가 표시되고, 지금까지 해석된 조인을 미리 채운 시각적 쿼리 빌더를 여는 **빌더에서 열기** 링크가 함께 나타납니다. 점이 없는 입력은 항상 raw-`WHERE` 동작을 유지합니다.

필터 입력 필드에서도 스키마 인식 자동 완성을 사용할 수 있습니다(빌더와 같은 탐색 — [Schema-aware autocomplete](QUERY_BUILDER.md#스키마-인식-자동-완성) 참조).

### 셀로 필터링

셀의 상황에 맞는 메뉴(`m` 또는 오른쪽 클릭)에 있는 **필터** 하위 메뉴는 `=`, `<>`, `<`, `>`, `LIKE`, `IS NULL` 및 열 타입이 허용하는 다른 연산자로 필터를 셀의 값으로 좁힙니다. 마지막 항목은 필터를 지웁니다. 셀을 가운데 버튼으로 클릭하면 같은 작업을 `=`로 한 번에 수행하고(NULL 셀은 `IS NULL`) 그 셀을 선택합니다. `Shift`와 함께 가운데 클릭하면 값을 제외합니다(`<>`, NULL 셀은 `IS NOT NULL`).

`=` 또는 셀 메뉴 맨 위의 **필터에 추가**는 선택한 셀을 추가합니다. 선택한 열마다 조건 하나를 만들며, 열의 값은 `열 = 값`으로, 그 열의 셀을 여러 개 선택했다면 `열 IN (...)`으로 각 값을 한 번씩 넣습니다. 어떤 방법이든 현재 필터를 `AND` 항으로 유지하며, 최상위 `OR`가 있으면 괄호로 감쌉니다. 따라서 `status = 500`은 `status = 500 AND "method" = 'getbets'`가 되고, 필터에 이미 있는 조건은 다시 추가되지 않습니다. 바이너리, JSON, 중첩 값은 이 방법으로 추가할 수 없습니다.

### 필터 실행 취소

테이블을 읽을 때 쓴 새 `WHERE` 필터는 적용한 방법(`Enter`, 기록 항목, 가운데 클릭 또는 `=`, 필터 하위 메뉴, 필터 지우기)과 관계없이 모두 그리드의 실행 취소와 다시 실행 단계가 됩니다. 그리드에 포커스가 있을 때 실행 취소는 먼저 테이블을 마지막으로 읽은 뒤에 한 셀 편집을 최신순으로 되돌리고, 그다음 이전 필터를 다시 넣어 첫 페이지부터 테이블을 읽습니다. 다시 실행도 같은 방식으로 앞으로 진행합니다. `WHERE` 필드에 키보드 포커스가 있는 동안에는 실행 취소와 다시 실행이 이전처럼 필드의 텍스트를 편집합니다. 필터 단계는 보류 중인 편집을 절대 버리지 않습니다. 실행 취소로 되돌릴 수 없는 편집이 있으면 다시 불러오기와 같은 메시지와 함께 거부됩니다. 되돌릴 편집이 없는 읽기 전용 그리드에서도 동작합니다. 정렬 순서와 `LIMIT` 변경은 실행 취소 단계가 아닙니다.

### 필터 기록

테이블을 성공적으로 읽은 모든 필터는 해당 테이블(연결, 데이터베이스, 스키마, 테이블)별로 최신순으로 테이블당 최대 50개까지 보관되며, 재시작 후에도 유지됩니다. 같은 필터를 다시 적용하면 두 번 나열되지 않고 맨 위로 이동하며, 데이터베이스가 거부한 필터는 보관되지 않습니다. 저장되는 것은 필터 텍스트뿐이며 행은 저장되지 않습니다.

`WHERE` 필드 왼쪽의 기록 아이콘, 테이블 메뉴(`m`)의 Toolbar 항목에 있는 **필터 기록**, 필드에서 `Ctrl+r`(macOS에서는 `Cmd+r`), 또는 필드가 비어 있거나 캐럿이 맨 앞에 있을 때 `Up` / `Down`으로 목록을 엽니다. 목록은 비어 있는 검색 필드에 키보드 포커스가 있는 상태로 열립니다. 검색 필드에 입력하면 입력한 모든 단어를 순서와 대소문자에 관계없이 포함하는 필터로 목록이 좁혀집니다. 예를 들어 `status 500`은 `status = 500 AND method = 'x'`를 찾습니다. 일치한 단어는 행에서 강조 표시되고, 가장 최근의 일치 항목이 `Enter`용으로 강조됩니다. `Up` / `Down`은 강조 표시를 옮기고, `Ctrl+r`을 다시 누르면 다음으로 오래된 일치 항목으로 이동하며, `Enter`는 강조된 필터를 적용합니다. `Shift+Delete` 또는 행의 ×는 그 필터를 제거하고, 마지막 행 **기록 지우기**는 테이블의 모든 필터를 지웁니다. `Escape`는 먼저 검색어를 지우고, 두 번째 `Escape`는 목록을 닫고 `WHERE` 필드로 돌아갑니다.

문서 컬렉션의 쿼리 기록(쿼리 바의 기록 버튼)도 같은 방식으로 재시작 후에도 유지됩니다.

### 비교 연산자 뒤의 따옴표

**WHERE 필터에서 비교 연산자 뒤에 따옴표 삽입**을 켜면(설정 → 일반 → 데이터 그리드, 기본값 끔) SQL 테이블의 텍스트 또는 날짜/시간 열 뒤에 비교 연산자를 입력할 때 값에 쓸 따옴표가 삽입됩니다. `method =`는 캐럿이 따옴표 사이에 놓인 `method = '|'`가 됩니다. 습관적으로 바로 뒤에 입력한 공백이나 따옴표는 흡수되고, 값을 입력한 뒤 닫는 따옴표 앞에서 `'`를 입력하면 따옴표를 하나 더 넣지 않고 그 위를 건너뛰며, 삽입 직후 `Backspace`를 누르면 따옴표가 다시 제거됩니다. 숫자, 불리언, `IS NULL`, `IN (...)`, 문자열 리터럴 안의 텍스트, 붙여넣은 텍스트에는 따옴표가 붙지 않습니다. 연산자는 [설정](SETTINGS.md)을 참조하세요.

## 유사한 행

벡터 열이 있는 테이블(현재는 pgvector `vector` 열이 있는 PostgreSQL 테이블)에서 `Shift+s`를 누르거나 행 메뉴에서 **유사한 행 찾기**를 선택하면 선택한 행과 가장 가까운 행을 보여 줍니다. 메뉴 항목은 읽을 열과 보여 줄 행 수를 표시하며, 실행할 수 없을 때는 그 이유를 표시합니다. 행의 해당 열에 값이 없거나, 그리드에 저장하지 않은 변경이 있어 먼저 저장하거나 되돌려야 하는 경우입니다.

- 열 선택기로 벡터 열을 고릅니다. 커서가 벡터 열에 있으면 그 열로 검색을 시작하고, 아니면 테이블의 첫 번째 벡터 열로 시작합니다.
- **L2**, **코사인**, **내적**으로 거리를 바꿉니다. 내적은 곱 자체를 큰 값부터 보여 줍니다.
- **K**는 보여 줄 행 수를 1부터 1000까지 정합니다.
- **테이블로 돌아가기** 또는 `Esc`는 필터를 유지한 채 테이블 페이지로 돌아갑니다.

선택한 행은 기본 키로 이웃에서 제외되고, 벡터가 없는 행은 나열되지 않으며, 유사한 행은 읽기 전용입니다. 숫자가 아닌 거리는 대시로 표시됩니다. `halfvec`과 `sparsevec` 열은 이 검색을 제공하지 않습니다.

## 편집과 CRUD

데이터 그리드에서:

- `o` — 행을 추가합니다.
- `x` — 선택한 행을 삭제합니다.
- `Delete` — 선택한 셀이 있는 모든 행을 삭제 대상으로 표시합니다.
- `r` — 이름 바꾸기 / 편집 (상황에 따라 다름).
- `y` — 선택한 행을 복사합니다.
- `Ctrl+c` (`Cmd+c`) — 선택한 셀을 클립보드로 복사합니다.

편집할 수 있는 테이블의 편집 막대는 데이터베이스 IDE처럼 **+**와 **−**로 시작합니다. **+**는 `o`처럼 활성 행 아래에 행을 추가하고, **−**는 `Delete`처럼 선택한 셀이 있는 모든 행을 삭제 대상으로 표시하며, 저장하면 평소의 확인을 거쳐 삭제합니다. **−**는 선택한 셀이 없을 때, **+**는 새 행을 받지 않는 테이블에서, 둘 다 유사한 행에서 비활성화되며, 도구 설명에 단축키나 비활성화된 이유가 표시됩니다.

여러 셀을 선택한 상태에서 `Enter`, `F2`를 누르거나 그중 한 셀을 더블클릭하면 모든 셀에 대한 편집기가 열리고, 상태 표시줄에 편집으로 바뀔 셀 개수가 표시됩니다. 확정한 값은 같은 열 유형이면서 값을 받을 수 있는 모든 선택된 셀에 저장하지 않은 변경 사항으로 기록되며, 저장과 되돌리기는 다른 편집과 똑같이 동작하고, 실행 취소(`u` 또는 `Ctrl+z`) 한 번으로 편집 전체가 취소됩니다. 읽기 전용 열의 셀, 삭제 표시된 행, 인라인 편집기가 편집하지 않는 값(JSON, 길거나 여러 줄인 텍스트)은 건너뛰며, 선택이 여러 행에 걸치면 키 열도 건너뜁니다. 모든 행의 키에 같은 값을 넣으면 저장할 수 없기 때문입니다. 열의 허용 값 목록에서 고른 값은 같은 목록을 가진 열에만 적용됩니다.

### 긴 값 편집

JSON 열과 긴 값은 모달 셀 편집기에서 열립니다. 내용이 JSON 객체나 배열, 또는
XML로 해석되는 텍스트 셀도 값 패널과 같은 방식으로 감지되어, JSON 열이 쓰는
것과 같은 편집기에서 열립니다. 보기 좋게 정렬되고, 구문 강조, 줄 번호와 접기,
텍스트가 여전히 유효한지 알려 주는 상태 줄, **Format**과 **Compact**가
있습니다. 제목에는 열 유형과 형식이 함께 표시됩니다. 예:
`raw_result 편집 (TEXT · JSON)`. 숫자나 문자열 하나만 있는 값은 일반 텍스트로
남습니다.

값을 보기 좋게 표시해도 저장 형식은 바뀌지 않습니다. 한 줄로 저장된 값은 다시
압축해 저장하며, 토큰 사이의 공백만 제거하므로 키 순서, `2312.64496440` 같은
숫자와 `"2725.8328350479"` 같은 문자열은 작성된 그대로 유지됩니다. 여러 줄로
저장된 값은 편집한 그대로 저장하고, 변경 없이 **Save**를 누르면 대기 중인 편집이
생기지 않습니다. 텍스트 열의 텍스트가 더 이상 유효하지 않으면 첫 번째
**Save**는 경고를 표시하고 두 번째는 입력한 그대로 저장합니다. JSON 열은 이를
거부합니다.

**Copy**는 저장하지 않은 편집을 포함해 편집기에 보이는 텍스트를 그대로 클립보드에
복사하고, **Copy compact**는 압축해서 복사합니다. 편집기의 오른쪽이나 아래쪽
가장자리, 또는 오른쪽 아래 모서리를 끌어 크기를 바꾸거나, 닫기 버튼 옆의 버튼으로
최대화할 수 있습니다. 크기는 다음 값을 열 때도 유지됩니다.

| 키 | 동작 |
|----|------|
| `Ctrl+s` (`Cmd+s`) | 저장 |
| `Ctrl+Shift+k` / `Ctrl+Shift+h` | 복사 / 압축하여 복사 (macOS에서는 `Cmd`) |
| `Ctrl+Shift+u` / `Ctrl+Shift+j` | 서식 / 압축 |
| `Ctrl+Shift+Enter` | 편집기 최대화 또는 복원 |

`Ctrl+c` (`Cmd+c`)는 계속 선택한 텍스트를 복사합니다.
### 셀의 SQL 식

MySQL, MariaDB, PostgreSQL, SQLite, SQL Server 테이블에서는 셀에 값 대신 `NOW()`, `"qty" + 1`, `DEFAULT` 같은 SQL 식을 넣을 수 있습니다. 식은 행의 `UPDATE` 또는 `INSERT`에 따옴표 없이 저장되고, 값은 데이터베이스가 계산합니다.

- 셀 컨텍스트 메뉴의 **SQL 식으로 편집…** 또는 `Ctrl+Alt+E`(macOS에서는 `Cmd+Alt+E`)를 누르면 `fx` 스위치가 켜진 편집기가 열립니다. 더 큰 선택 영역의 셀에서는 여러 셀 편집처럼 선택된 모든 셀에 식이 들어갑니다.
- 편집기가 열린 상태에서 `fx`를 클릭하거나 같은 단축키를 누르면 입력한 내용을 유지한 채 값과 식 사이를 전환합니다.
- `fx`가 켜져 있으면 편집기 아래 목록에 열의 타입과 데이터베이스에 맞는 식이 제안되며, `Down` / `Up`으로 하나씩 편집기에 입력됩니다. 다른 식을 직접 입력할 수도 있습니다.

| 열 타입 | MySQL / MariaDB | PostgreSQL | SQLite | SQL Server |
|---|---|---|---|---|
| 날짜와 시간 | `NOW()`, `CURRENT_TIMESTAMP`, `UTC_TIMESTAMP()`, `DATE_ADD(NOW(), INTERVAL 1 DAY)` | `now()`, `current_timestamp`, `now() + interval '1 day'` | `CURRENT_TIMESTAMP`, `datetime('now')`, `datetime('now', 'localtime')`, `datetime('now', '+1 day')` | `GETDATE()`, `CURRENT_TIMESTAMP`, `SYSDATETIME()`, `GETUTCDATE()`, `DATEADD(day, 1, GETDATE())` |
| 날짜 | `CURDATE()`, `CURRENT_DATE`, `UTC_DATE()` | `current_date`, `current_date + 1` | `CURRENT_DATE`, `date('now')` | `CAST(GETDATE() AS date)` |
| 시간 | `CURTIME()`, `CURRENT_TIME`, `UTC_TIME()` | `current_time`, `localtime` | `CURRENT_TIME`, `time('now')` | `CAST(GETDATE() AS time)` |
| uuid | `UUID()` (`char(36)`), `UNHEX(REPLACE(UUID(), '-', ''))` (`binary(16)`) | `gen_random_uuid()` | | `NEWID()` |
| 숫자 | `col + 1`, `col - 1` | 동일 | 동일 | 동일 |
| 텍스트 | `CONCAT(col, '')`, `UPPER`, `LOWER`, `TRIM` | `col \|\| ''`, `upper`, `lower`, `trim` | `col \|\| ''`, `upper`, `lower`, `trim` | `CONCAT(col, '')`, `UPPER`, `LOWER`, `LTRIM(RTRIM(col))` |
| 모든 타입 | `NULL`, `DEFAULT` | `NULL`, `DEFAULT` | `NULL` | `NULL`, `DEFAULT` |

저장 전의 식은 셀에 기울임꼴 `fx NOW()`로 표시되고, 저장한 뒤에는 데이터베이스가 계산한 값이 행에 표시됩니다. 실행 취소, 다시 실행, 되돌리기는 다른 편집과 똑같이 동작하며, 새 행의 셀에도 식을 넣을 수 있습니다. 주석, `;`, 괄호 밖의 `,`가 들어 있는 식은 셀보다 더 많은 것을 바꿀 수 있으므로(주석이 `UPDATE`의 `WHERE`를 가릴 수 있음) 확정할 때 거부됩니다. 다른 데이터베이스, 쿼리 결과, 문서 컬렉션에서는 식을 제공하지 않습니다.

### 저장 전에 변경 사항 검토

편집 막대에서 저장과 되돌리기 옆의 **검토**를 누르거나 `Ctrl+Alt+S`(macOS에서는 `Cmd+Alt+S`)를 누르면, 테이블의 저장하지 않은 변경 사항에 대해 저장이 실행할 문을 실행 순서대로(삭제, 새 행, 편집한 행) 보여 줍니다. 문은 저장 과정이 직접 만들고 연결의 드라이버가 생성하므로, 데이터베이스가 받는 그대로이며 SQL 식은 따옴표 없이 들어갑니다. 값은 리터럴로 문에 들어가며, MySQL, MariaDB, PostgreSQL, SQLite, SQL Server 드라이버는 바인드 매개변수를 보내지 않습니다. 저장할 수 없는 변경(키가 없는 행)은 이유를 적은 주석으로 표시됩니다.

검토 창에서 **저장**(또는 `Enter`)은 삭제 시 따로 묻는 확인 없이 그 문을 실행하고, **SQL 복사**는 스크립트로 복사하며, **취소**(또는 `Escape`)는 변경 사항을 유지한 채 창을 닫습니다. 설정 > 일반 > 데이터 그리드에서 **저장 전에 변경 사항 검토**를 켜면 테이블 그리드에서 저장할 때마다 먼저 검토 창이 열립니다.

### 생성된 ID

셀에 DBFlux가 생성한 새 식별자를 일반 값으로 넣을 수 있어 모든 데이터베이스에서 동작합니다: **UUID v4**(무작위), **UUID v7**(시간 순), **KSUID**(27자, 초 단위 정렬), **ULID**(26자, 밀리초 단위 정렬).

- 셀 컨텍스트 메뉴의 **값 설정 ▸**에 열이 저장할 수 있는 종류마다 항목이 있습니다. 더 큰 선택 영역의 셀에서는 선택된 셀마다 복사본이 아닌 자신만의 새 값을 받으며, 실행 취소 한 번으로 모두 되돌립니다.
- 식별자처럼 보이는 열(`uuid` 타입, 키, 어떤 종류에 맞는 길이의 텍스트 열, `user_id` 같은 이름)에서는 인라인 편집기 아래 목록에 종류가 먼저(UUID가 맨 위) 나오며, `Down` / `Up`으로 새 값을 편집기에 입력합니다. 여러 셀 선택에서 확정하면 역시 셀마다 자신만의 값을 받습니다.
- 셀 편집기 대화 상자에는 종류마다 **… 생성** 버튼이 있습니다.

`uuid` 또는 `uniqueidentifier` 열은 하이픈이 들어간 형식의 UUID를 받습니다. 텍스트 열은 선언된 길이에 맞는 종류를 받습니다: `char(36)`는 UUID, `char(27)`는 KSUID, `varchar(30)`는 KSUID나 ULID, 길이를 모르는 열은 네 가지 모두입니다. MySQL의 `binary(16)` 같은 바이너리 열에는 생성된 ID를 제공하지 않습니다. 그리드는 텍스트를 쓰지만 이런 열에는 16바이트 원시 값이 필요하기 때문이며, 대신 `UNHEX(REPLACE(UUID(), '-', ''))` 식을 사용합니다.

### 결과를 편집할 수 있는 경우

기본 키가 있는 테이블의 단순 테이블 조회는 편집할 수 있습니다. **시각적 쿼리 빌더**(SELECT 모드)가 만든 결과도 편집할 수 있지만, 하나의 테이블에 확실하게 바인딩된 경우뿐입니다. 즉, 결과가 하나의 기반이 되는 테이블과 1:1로 대응하고 그 테이블의 모든 기본 키 열이 원래 이름 그대로 프로젝션되어 있어야 합니다. 이 경우 편집과 삭제는 프로젝션된 기본 키 값으로 `WHERE`를 만듭니다.

JOIN은 허용됩니다. 소스 테이블의 열은 편집할 수 있고, 조인된 열은 읽기 전용입니다.

빌더 결과는 다음 중 하나에 해당하면 그 이유를 설명하는 도구 모음 힌트와 함께 **읽기 전용**으로 동작합니다:

- 쿼리가 집계를 하거나 `GROUP BY` / `HAVING`을 사용합니다.
- 프로젝션이 JOIN 전체에 대한 와일드카드입니다.
- 기본 키 열이 없거나 별칭으로 프로젝션되었습니다.
- 테이블의 키가 아직 스키마 캐시에서 로드되지 않았습니다(키가 도착하면 그리드는 스스로 편집 가능 상태로 전환됩니다).

편집기에 직접 입력한 자유 형식 SQL은 읽기 전용으로 유지됩니다. 인라인 편집은 단순 테이블 조회와 빌더가 만든 SELECT에만 적용됩니다.

### 집계된 결과

결과가 그룹화된(`GROUP BY`) 쿼리에서 나온 것이면 행은 집계된 출력을 표시하고 편집은 비활성화됩니다. 행 추가, 행 삭제, 셀 편집, 행 검사를 사용할 수 없으며 그 이유를 설명하는 도구 설명이 표시됩니다. 페이지 나누기는 기반이 되는 행이 아니라 그룹화된 행을 기준으로 세므로 페이지 합계가 정확합니다. 집계 열은 올바른 열 유형을 유지하므로 차트 작성도 여전히 동작합니다.

## CSV 또는 JSON으로 복사

테이블 결과의 상황에 맞는 메뉴에서 **복사** 아래의 **다른 형식으로 복사 ▸** 하위 메뉴는
**CSV**와 **JSON**으로 시작합니다. 하나의 범위든 `Ctrl`+클릭으로 고른 여러 범위든 선택 영역을 **불러온 행을
클립보드에 복사**와 같은 내보내기로 복사합니다. CSV는 열 이름으로 된 머리글 행으로
시작하고, JSON은 행마다 열 이름을 키로 하는 객체 하나씩을 담은 배열이며 숫자, 불리언,
`null`은 그대로 유지됩니다. 선택 영역이 걸친 모든 행과 열이 포함되며, 그 안에 있지만
선택되지 않은 셀은 CSV에서는 비어 있고 JSON에서는 `null`입니다. 복사는 그리드에 보이는
그대로 따릅니다. 저장하지 않은 편집은 새 값으로, 아직 저장하지 않은 추가 행은 그 위치에
복사됩니다. JSON에서 이름이 같은 열(조인의 `a.id`와 `b.id`)은 키 하나를 공유하며 마지막
열의 값을 갖습니다. 일반 **복사**(`Ctrl+c`)도 저장하지 않은 편집과 추가 행을 포함해
탭으로 구분된 텍스트를 복사하며, 설정 → 일반 → 데이터 그리드의 **복사할 때 열 이름 포함**을
켜면 복사한 열의 이름 한 줄로 시작하고, 끄면 머리글 없이 복사합니다.
`Ctrl+Alt+c`(macOS에서는 `Cmd+Alt+c`)를 누르면 키보드로 **JSON으로 복사**가 실행되며,
메뉴의 해당 항목 옆에 이 단축키가 표시됩니다.

하위 메뉴에는 그 아래에 추출 항목이 세 가지 더 있습니다.

- **SQL IN 목록으로 복사**는 한 열에서 선택한 값을 `WHERE ... IN`에 쓸 목록으로 복사합니다. 예: `('a', 'O''Brien')`, `(1, 2, 3)`. 따옴표는 연결의 드라이버가 리터럴을 쓰는 방식을 따르고, 연결이 없는 결과에서는 ANSI 방식입니다. 여러 번 선택한 값은 한 번만 넣고, `IN (NULL)`은 아무것도 일치하지 않으므로 `NULL`은 뺍니다. NULL만 선택하면 아무것도 복사하지 않고 그 이유를 알려 줍니다. 여러 열을 선택하면 가장 왼쪽 열을 사용합니다. 컬렉션의 메뉴에는 나타나지 않습니다.
- **INSERT 문으로 복사**는 테이블에서 선택한 행마다 선택한 열로 `INSERT` 하나씩을 복사하며, **쿼리로 복사**와 같은 드라이버 생성기로 작성합니다. 선택 영역 안의 셀이 직접 선택되지 않았더라도 각 행은 그 열의 자기 값을 쓰며, 드라이버가 쓸 수 없는 값이 있는 행은 뺍니다. 그룹화된 행이나 쿼리 빌더의 조인 결과에는 모든 열이 그 테이블의 열이 아니므로 제공되지 않습니다.
- **Markdown 표로 복사**는 CSV로 복사와 같은 행과 열을 머리글 행이 있는 Markdown 표로 복사합니다. `NULL`과 선택되지 않은 셀은 비어 있고, 바이트는 `\x` 16진수로, 배열과 문서는 JSON으로 쓰며, 값 안의 `|`, `&`, `<`와 줄바꿈은 이스케이프됩니다.

세 항목 모두 CSV로 복사와 같이 그리드에 보이는 그대로 복사합니다. 저장하지 않은 편집은 새 값으로, 그리드에서 추가하고 아직 저장하지 않은 행은 그 위치에 복사됩니다.

## 쿼리로 복사

**다른 형식으로 복사 ▸** 하위 메뉴는 행을 쿼리로 복사하는 항목(INSERT, UPDATE, DELETE, 연결의 언어를 나타내는 제목 아래)으로 끝나며, 문서 보기의 메뉴에서는 별도의 하위 메뉴로 남아 있습니다. 선택한 행에서 드라이버 고유의 쿼리 생성기를 사용해 드라이버별 변경 문(비 SQL 드라이버의 경우 봉투)을 생성합니다.

## 내보내기

결과 패널에서 `Ctrl+e` (`Cmd+e`)를 누르거나 명령 팔레트에서 **결과 내보내기**를 실행합니다. 사용할 수 있는 형식은 결과 형태에 따라 다르며 다음을 포함합니다:

- **CSV**
- **JSON (pretty)** 및 **JSON (compact)**
- **텍스트**
- **바이너리** (바이너리 형태의 결과용)

메뉴 위쪽에서 무엇을 내보낼지 고르며, 그 아래의 **파일로 저장**과 **클립보드로 복사** 형식은 이 선택을 따릅니다.

- **행**: **선택**은 선택된 셀이 있는 행을 CSV로 복사처럼 그리드에 보이는 그대로(저장하지 않은 편집과 추가 행 포함), **불러온 행**은 그리드가 가진 행(테이블에서는 현재 페이지)을, **전체**는 테이블이나 컬렉션의 모든 행을 기록합니다(아래 참고. 그리드가 페이지 단위로 다시 읽을 수 있을 때만 제공됩니다). 셀을 선택하기 전까지 **선택**은 비활성화되며, 그 이유가 행 아래에 표시됩니다.
- **열**: 기본값인 **표시**는 그리드에 보이는 열을 화면 순서대로 기록하므로 숨긴 열은 빠지고 옮기거나 고정한 열은 자리를 유지합니다. **전체**는 숨긴 열을 포함한 모든 열을 결과 순서대로 기록합니다. **선택**은 선택된 셀이 있는 보이는 열을 화면 순서대로 기록합니다. 선택한 행과 선택한 열을 함께 고르면 선택한 범위의 셀을 값과 함께 기록하며, `Ctrl`+클릭으로 여러 범위를 고른 경우 그 범위들이 걸친 모든 행과 열을 기록합니다.
- 기본으로 켜져 있는 **헤더 행 포함 (열 이름)**과 **구분자**(쉼표, 세미콜론, 탭)는 이 메뉴에서 저장하거나 복사하는 CSV와 CSV로 모든 행 내보내기에 적용됩니다. 컨텍스트 메뉴의 CSV로 복사에는 영향을 주지 않습니다.

옵션 위의 제목은 형식이 무엇을 기록하는지 알려 줍니다(예: "내보내기: 선택한 행 12개, 열 4개"). 저장하거나 복사한 뒤의 알림도 같은 행과 열을 경로 또는 바이트 수와 함께 표시합니다. 메뉴는 첫 번째 형식에서 열리므로 `Ctrl+e` `Enter`로 바로 저장할 수 있습니다. `k` 또는 `Up`으로 옵션으로 올라가고, 옵션 행에서 `Enter`, `Right` 또는 `l`을 누르면 적용되지 않는 값을 건너뛰고 다음 값으로 바뀌거나 헤더 체크박스가 전환됩니다. 값을 클릭하면 바로 선택됩니다. 선택은 테이블별이 아니라 모든 그리드에 대해, 다시 시작한 뒤에도 유지됩니다.

**행**을 **전체**로 두면 메뉴에 **모든 행을 파일로 내보내기**가 나타나며, CSV 또는 한 줄에 객체 하나인 JSON으로 내보낼 수 있습니다. 그리드의 현재 필터, 정렬, 열 선택으로 테이블이나 컬렉션 전체를 한 페이지씩 다시 읽고 **열** 옵션이 고른 열을 기록하여 선택한 하나의 파일에 스트리밍하므로 데이터 전체가 메모리에 올라갈 필요가 없습니다. 쿼리 빌더나 관계형 필터로 표시된 테이블은 같은 쿼리로 읽으며, 그 쿼리의 오프셋에서 시작하고 한도가 있으면 한도에서 멈춥니다. 내보내기는 작업 패널의 작업으로 실행되며, 작업 패널에서 진행 상황을 보고 취소할 수 있습니다. 알림에는 전체 행 수와 경로가 표시됩니다.

문서 컬렉션을 JSON으로 내보내면 각 문서를 모든 필드와 함께 한 줄에 하나의 객체로 그대로 기록합니다. CSV로 내보내면 그리드가 첫 페이지에 보여 주는 열(펼친 객체 포함)로 기록됩니다. 한 컬렉션의 문서가 같은 필드를 가질 필요는 없으므로, CSV에서는 이후 페이지에서 처음 나타난 필드가 이미 기록된 헤더에 없어 열을 갖지 못합니다. 이 경우 내보내기는 해당 필드를 경고로 알려 줍니다.

쿼리 결과는 모든 행을 내보내려면 쿼리를 다시 실행해야 하므로 불러온 행만 제공합니다. 최근접 이웃 검색도 마찬가지입니다. 이 검색은 가장 가까운 행을 정해진 수만큼 반환하며, 그리드에 이미 모두 들어 있습니다.
