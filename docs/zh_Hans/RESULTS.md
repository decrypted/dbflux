# 处理结果

结果渲染在文档内的结果标签页中。每个表或集合以其驱动为该对象声明的视图打开，并提供其声明的其他视图：

- 关系型表和查询结果使用**表格视图**。
- 文档集合（例如 MongoDB、DynamoDB）使用**树视图**，同一页数据还可用**表格**和 **JSON** 视图查看（见[文档集合](DOCUMENTS.md)）。
- 含 JSON 列的表使用**表格视图**，并提供同一批行的**树**视图（见[表中的 JSON 列](DOCUMENTS.md#表中的-json-列)）。
- 时间序列（例如 InfluxDB 的 measurement 或 TimescaleDB 的 hypertable）在其行可以绘制图表时使用**网格上方的图表**（见[时间序列表和集合](CHARTS.md#时间序列表和集合)）。
- Redis 使用**键值视图**（见[键值视图](KEY_VALUE.md)）。

当驱动声明了事件流呈现方式时，事件流类型的容器会作为事件流打开。

含向量列的表还可以列出与所选行最[相似的行](#相似行)。

## 结果显示在编辑器旁边

在查询标签页中，结果显示在编辑器下方。在宽屏上，可以通过结果标题栏中的面板按钮、窗格操作中的 **在右侧显示结果** 或命令面板中的 **将结果移到编辑器旁边或下方**，将结果移到编辑器右侧。同一控件可将结果移回下方。拖动分隔线可调整两侧大小。新的查询标签页会使用上次选择的位置。

无论结果位于哪个位置，按 `Ctrl+j` 都会将键盘焦点从编辑器移到结果，按 `Ctrl+k` 则移回编辑器。

## 浏览数据网格

当结果面板获得焦点时：

- `j`/`k`（或 `Down`/`Up`）— 选择下一项 / 上一项。
- `h`/`l`（或 `Left`/`Right`）— 左移 / 右移一列。
- `g`/`Shift+g`（或 `Home`/`End`）— 选择第一项 / 最后一项。
- `Ctrl+d`/`Ctrl+u`（或 `PageDown`/`PageUp`）— 向下 / 向上翻页。
- `[` / `]` — 结果上一页 / 下一页。
- `f` 聚焦工具栏；`/` 聚焦搜索 / 筛选框。
- `z` 切换面板。
- `m`（或 `Shift+F10`）打开行 / 单元格上下文菜单。
- `=` 把选中单元格的值添加到表的 `WHERE` 筛选（参见[按单元格筛选](#按单元格筛选)）。

单元格上下文菜单（`m`、`Shift+F10` 或右键）经过分组，能完整显示在屏幕上。顶部是 **复制**、**复制为 ▸**（CSV、JSON、SQL IN 列表、INSERT 语句、Markdown 表格，在表中还有把行复制为查询）、**查看值** 和 **添加到筛选**。接着是编辑项：**编辑**、**在编辑器中编辑…**、**粘贴** 和 **设置值 ▸**（列默认值、列类型提供的值、NULL、表达式… 以及该列可接受的标识符，参见[单元格中的 SQL 表达式](#单元格中的-sql-表达式)）。然后是 **筛选 ▸**、**排序 ▸**、**列 ▸**（隐藏、移动、固定、适应宽度、列…）和 **行 ▸**（检查、添加、复制行、连接自身的行操作，以及单独放在最后的删除行）。最后是 **更多 ▸**（生成 SQL ▸、将此查询制作成图表、查找相似行）和 **工具栏 ▸**。每部分只显示适用于该单元格的项，每行保留其快捷键。`Up` / `Down` 在菜单中移动，`Enter` 或 `Right` 运行某行或打开其子菜单，`Left` 或 `Escape` 返回上一级。在窗口底部或右边缘附近打开的菜单会向上打开或向左移动，子菜单在有空间的一侧打开，比窗口还高的菜单会滚动并保持高亮行可见；列标题菜单和导出菜单也以同样方式适应窗口。

在表或结果网格中，`m` 和 `Shift+F10` 在选中的单元格上打开菜单。如果单元格已滚动到视图之外，菜单在网格靠该方向的边缘打开，并避开表头、滚动条和固定列。记录视图中菜单留在视图内，但不会对准选中的字段。在文档集合的树中，菜单在面板左上角附近的固定位置打开，而不是在节点上。

使用鼠标时，单击选择一个单元格，`Shift`+单击或按住拖动选择到另一个单元格的范围。单击行号选择整行，在另一个行号上 `Shift`+单击选择其间的所有行。在单元格或行号上 `Ctrl`+单击（macOS 上为 `Cmd`+单击）会将其加入选择，若它是唯一选中的则取消选择；复制多个范围时会复制其覆盖的行和列，未选中的单元格留空。添加的范围用于复制：删除、复制行、保存等行操作作用于光标所在的行，右键单击会选中指针下的单元格，记录视图将 `Ctrl`+单击视为普通单击。拖动超出网格边缘时，网格会朝该方向滚动，指针离得越远滚动越快，并持续扩展范围，直到松开按钮或指针移回。

当选区包含多个单元格时，状态栏会显示单元格数量，以及其中数字的总和、平均值、最小值和最大值。NULL 和文本会计入数量，但不参与计算，状态栏会说明跳过了多少个。合计基于已加载的行（包括未保存的编辑）计算，不会再次查询数据库。

## 列标题菜单

右键点击列标题可打开仅针对该列的菜单：复制列名、升序或降序排序、清除排序，以及全部筛选运算符，
全部在一个平铺列表中。表格菜单（`m`）也为活动单元格所在的列提供**复制列名**，因此键盘同样可以使用。左键点击列标题选择整列（`Shift`+单击选择到该列的所有列，`Ctrl`+单击（macOS 上为 `Cmd`+单击）添加或移除该列）；点击标题右侧的箭头循环切换排序，列未排序时显示一个浅色的上下箭头。开启 **点击列标题时对该列排序**（Settings > General > Data grid）后，普通点击列标题会像箭头一样对该列排序。

要按多列排序，`Shift`+单击另一列的箭头：该列成为下一个排序键（升序），再次 `Shift`+单击变为降序，
再按一次则从排序中移除。箭头会独自处理这次点击，因此在箭头上 `Shift`+单击不会像在标题其他位置那样扩展列选区。有多个排序键时，每个已排序列标题的箭头旁会显示它的顺序（1、2、3），
第一个键相同的行按第二个键排序，依此类推。普通单击任意箭头会重新只按该列排序，若该列已是排序键则保持原方向。主键包含多列的表打开时按所有主键列排序，
因此这些键列一开始就显示 1、2。列菜单以及单元格菜单的 **排序 ▸** 中的
**添加到排序：列 ASC** 和 **添加到排序：列 DESC** 作用相同，对已经是排序键的列只改变方向；
**移除排序**会移除所有排序键。表会把所有排序键作为一个 `ORDER BY` 发送给数据库；查询结果在内存中排序。
如果表仍处于默认顺序（主键），第一个添加的键会取代该顺序，因为先按主键排序的行不会留下可供其他列排序的并列行；
清除排序后回到默认顺序。
按 `Shift+m` 可以用键盘为所选单元格所在的列打开同一个菜单。菜单末尾是视图设置的
**列** 分区，它只改变表格显示该列的方式，从不改变查询。**适应宽度** 按列标题和已加载
的值调整列宽，最多 640 像素，这样一个很长的 JSON 值不会把表格的其余部分挤出屏幕；
双击标题右边界上的调整宽度边缘效果相同。

**隐藏列** 将该列从屏幕上移除，**列…** 列出所有列并在显示的列上打勾：`Enter`、`Space`
或单击会显示或隐藏高亮的列，列表保持打开，**显示所有列** 恢复所有隐藏的列，`Escape`
关闭列表。**左移** 和 **右移** 将该列移动一位；把一个标题拖到另一个标题上，会把该列移到
那个位置。

**固定列** 让该列在表格横向滚动时保持在左边缘、紧挨行号，就像冻结窗格：在很宽的日志表中
固定 `id` 和 `created_at`，它们就始终可见。固定的列按固定的先后顺序排在表格最前面，标题上
显示一个图钉；**取消固定列** 让该列重新随其他列滚动，排在它们的第一位。选择、编辑、排序、
调整宽度和行号在固定列上同样可用。左移和右移不会越过固定边界；把标题拖过边界会固定或取消
固定该列。固定的列最多占表格宽度的三分之二，其余列始终留有空间：表格较窄时，超出部分的
固定列会随其他列滚动，直到表格重新变宽。

查询仍然读取所有列（表仍然执行 `SELECT *`）；要在查询本身中去掉某列，请使用查询构建器的
投影。复制、复制为 CSV 和复制为 JSON 跟随屏幕：即按表格显示的顺序复制显示的列。复制行、
复制为查询和导出使用结果原有顺序的整行，包括隐藏的列。表会按连接、数据库、模式和表记住
其布局，关闭后重新打开或重启 DBFlux 后依然保留；把所有列恢复为表原有的顺序并全部显示，
就会忘记该布局。查询结果在其标签页打开期间保留布局。文档表格保持其字段顺序，只提供
“适应宽度”。

## 值面板

右键点击单元格并选择 **查看值**，或按 `v`，即可在右侧检查器栏中打开该单元格。面板会以
JSON、XML 或纯文本显示值（根据内容检测，且仅在确实能解析时），并提供格式化、压缩和自动换行。
可以直接在面板中编辑：**保存** 会直接提交该行，**还原** 会放弃更改。在网格中移动时面板会
跟随所选单元格，但在有未保存更改时不会跟随。

二进制单元格（`bytea`、`BLOB`、`varbinary` 等）以只读的十六进制转储打开。如果其字节是 PNG、
JPEG、GIF、WebP 或 BMP 图片（根据字节本身识别，而不是根据列名），面板会改为显示图片，缩小到
适合面板的大小，并在下方显示像素尺寸、格式和字节大小。**十六进制** 切换到十六进制转储，**图片**
切换回图片。**图片另存为…** 将存储的字节写入文件，**复制图片** 将图片放到剪贴板；两者也都在
表格上下文菜单（`m`）的“工具栏”项中。以 base64 保存图片的文本单元格（无论是裸 base64 还是
`data:image/...;base64,` URI）也会同样以图片打开，并可用 **文本** 切换回文本。

超过 32 MB 或 3200 万像素的图片不会解码，在图片结束之前就结束的值（例如被大小限制截断的值）也
不会解码：面板会在十六进制转储上方说明原因。动图只显示第一帧，SVG 不会绘制。大值的十六进制
转储只显示前 64 KB。

## 行检查器

按 `Ctrl+Space`，或右键点击某行并选择 **检查行**，即可在右侧检查器栏中打开所选行。它列出该行的
每一列及其值，并标出主键列和外键列。在网格中移动时检查器会跟随所选行；标题中的固定按钮可让它停留在
当前行。当结果可编辑时，底部的 **编辑**、**复制** 和 **删除** 作用于被检查的行。再次按 `Ctrl+Space`
或点击关闭按钮即可关闭。

在 **引用** 下，检查器会从两个方向列出该行的外键：

- **传出** — 该行的某个单列外键指向另一张表。条目会标出那张表以及它指向的行：解析完成后显示被引用行
  的可读标签（如 "María López · #8"），解析前显示其键值。点击条目即可在那行上打开被引用的表：DBFlux
  会复用该表已有的标签页（没有则新开一个），并把其筛选替换为主键相等条件，使被引用的行正好处于视图中。
- **传入** — 其他表的外键指向该行。每个条目标出表名，并统计该表中有多少行引用它；计数在后台加载。
  这些条目仅用于参考。

网格中的外键单元格也可以在 ID 旁显示同样的被引用行标签：在[设置](SETTINGS.md)中开启
**在外键单元格中显示被引用行的标签**。无论该设置是否开启，行检查器都会解析引用。

## 筛选结果

数据网格工具栏有一个 `WHERE` 筛选输入框，会带上你输入的条件重新执行查询。对于 SQL 连接，它支持两种写法：

- **原生 `WHERE`** — 输入一个普通条件（例如 `status = 'active'`）。这是默认行为。
- **关系型（ORM 风格）路径** — 输入一个沿外键前进的点分路径，例如 `created_by.email LIKE '%@acme.com'` 或 `created_by.organization.name = 'Acme'`。DBFlux 会依据表的外键元数据解析该路径，并自动连接到被引用的表，无需手工编写 JOIN。

当关系型筛选解析成功时，会显示一个标签，说明它添加了多少个连接。如果某一段存在歧义或无法解析，会出现内联错误，并附一个 **在构建器中打开** 链接，用于打开可视化查询构建器，并预填已解析出的连接。不含点号的输入始终保持原生 `WHERE` 行为。

筛选输入框同样提供 Schema 感知自动补全（导航方式与构建器相同，参见[Schema 感知自动补全](QUERY_BUILDER.md#schema-感知自动补全)）。

### 按单元格筛选

单元格上下文菜单（`m` 或右键）中的 **筛选** 子菜单，会用 `=`、`<>`、`<`、`>`、`LIKE`、`IS NULL` 以及该列类型允许的其他运算符，把筛选条件缩小到该单元格的值。其最后一项清除筛选。用鼠标中键单击单元格会一步完成同样的 `=` 筛选（NULL 单元格为 `IS NULL`），并选中该单元格；按住 `Shift` 中键单击则排除该值（`<>`，NULL 单元格为 `IS NOT NULL`）。

`=` 或单元格菜单顶部的 **添加到筛选** 会添加选中的单元格：每个选中的列一个条件，该列的值写成 `列 = 值`，若选中了该列的多个单元格则写成 `列 IN (...)`，每个值只出现一次。所有方式都会把当前筛选条件保留为一个 `AND` 项，当其包含顶层 `OR` 时加上括号，因此 `status = 500` 会变为 `status = 500 AND "method" = 'getbets'`；筛选条件中已有的条件不会重复添加。二进制、JSON 和嵌套值无法通过这种方式添加。

### 撤销筛选

读取表时使用的每个新 `WHERE` 筛选条件都是网格撤销与重做的一步，无论它是如何应用的（`Enter`、历史条目、中键单击或 `=`、筛选子菜单、清除筛选）。焦点在网格上时，撤销会先按从新到旧撤回自上次读取表以来的单元格编辑，然后恢复上一个筛选条件并从第一页重新读取表；重做以同样方式前进。`WHERE` 字段持有键盘焦点时，撤销与重做仍像以前一样编辑其文本。筛选步骤绝不会丢弃待提交的编辑：存在撤销无法撤回的编辑时，会以与重新加载相同的提示拒绝。它在只读网格中同样有效，那里没有可撤销的编辑。排序和 `LIMIT` 的更改不是撤销步骤。

### 筛选历史

表成功读取时使用的每个筛选条件都会按表（连接、数据库、Schema 和表）保存，最新的在前，每个表最多 50 条，重启后仍然保留。再次应用某个筛选条件会把它移到最前面，而不会重复列出；被数据库拒绝的筛选条件不会保存。只保存筛选文本，从不保存行数据。

可以通过 `WHERE` 字段左侧的历史图标、表格菜单（`m`）中 Toolbar 项下的 **筛选历史**、在字段中按 `Ctrl+r`（macOS 上为 `Cmd+r`），或在字段为空或光标位于开头时按 `Up` / `Down` 打开列表。列表打开时，键盘焦点位于其搜索框中，搜索框初始为空。在搜索框中输入时，列表会缩小为包含所输入全部单词的筛选条件，不分顺序、不区分大小写：`status 500` 会找到 `status = 500 AND method = 'x'`。匹配的单词会在行中高亮显示，最新的匹配项会被高亮，供 `Enter` 使用。`Up` / `Down` 移动高亮，再次按 `Ctrl+r` 会移到下一个更早的匹配项，`Enter` 应用高亮的筛选条件。`Shift+Delete` 或行上的 × 会删除该筛选条件，最后一行 **清除历史** 会清除该表的全部筛选条件。`Escape` 先清空搜索；再按一次 `Escape` 会关闭列表并回到 `WHERE` 字段。

文档集合的查询历史（其查询栏的历史按钮）同样会在重启后保留。

### 比较运算符后的引号

开启 **在 WHERE 筛选中比较运算符后插入引号**（设置 → 通用 → 数据网格，默认关闭）后，在 SQL 表的文本或日期/时间列后输入比较运算符，会为其值插入引号：`method =` 变为 `method = '|'`，光标位于两个引号之间。紧接着出于习惯输入的空格或引号会被吸收；输入值之后，在右引号前输入 `'` 会跳过它，而不是再添加一个；插入后立即按 `Backspace` 会再次删除这对引号。数字、布尔值、`IS NULL`、`IN (...)`、字符串字面量内的文本以及粘贴的文本不会加引号。运算符见[设置](SETTINGS.md)。

## 相似行

在含向量列的表上（目前是含 pgvector `vector` 列的 PostgreSQL 表），按 `Shift+s` 或在行菜单中选择 **查找相似行**，即可列出与所选行最接近的行。菜单项会注明它读取的列和列出的行数，或说明无法运行的原因：该行在这一列中没有值，或网格中有未保存的更改，需要先保存或还原。

随后网格会把所选行固定在顶部并标记为 `参照行`，下方按由近到远的顺序显示与它最接近的 10 行。第一列是距离，列标题会写明距离类型。一个工具栏会取代筛选行：

## 编辑与增删改查

在数据网格中：

- `o` — 添加行。
- `x` — 删除选中的行。
- `Delete` — 把每个含有选中单元格的行标记为删除。
- `r` — 重命名 / 编辑（随上下文而定）。
- `y` — 复制选中的行。
- `Ctrl+c`（`Cmd+c`）— 把选中的单元格复制到剪贴板。

可编辑表的编辑栏以 **+** 和 **−** 开头，与数据库 IDE 中一样：**+** 像 `o` 一样在活动行下方添加一行，**−** 像 `Delete` 一样把每个含有选中单元格的行标记为删除，保存时经过通常的确认后删除。未选中任何单元格时 **−** 不可用，不接受新行的表上 **+** 不可用，相似行中两者都不可用；它们的提示会显示快捷键或不可用的原因。

选中多个单元格时，按 `Enter`、`F2` 或双击其中一个单元格，会为所有选中单元格打开编辑器，状态栏会显示此次编辑将更改多少个单元格。提交的值会写入每个列类型相同且可以接受它的选中单元格，作为未保存的更改，保存和还原与其他编辑一样处理，一次撤销（`u` 或 `Ctrl+z`）即可撤回整个编辑。只读列中的单元格、标记为删除的行以及内联编辑器不编辑的值（JSON、较长或多行文本）会被跳过；当选区跨越多行时，主键列也会被跳过，因为在每一行的主键中写入同一个值永远无法保存；从某列的允许值列表中选择的值只会写入具有相同列表的列。

### 编辑长值

JSON 列和长值会在模态单元格编辑器中打开。内容能解析为 JSON 对象或数组、或解析为
XML 的文本单元格，也会以与值面板相同的方式被识别，并在 JSON 列所用的同一个编辑器中
打开：格式化显示，带语法高亮、行号和折叠，有一行状态说明文本是否仍然有效，并提供
**Format** 和 **Compact**。标题同时写出列类型和格式，例如
`编辑 raw_result（TEXT · JSON）`。单独的数字和字符串仍按纯文本处理。

格式化显示不会改变值的存储方式。存储为单行的值会再次以紧凑形式保存，只去掉记号之间
的空白，因此键的顺序、`2312.64496440` 这样的数字和 `"2725.8328350479"` 这样的字符串
都保持原样。存储为多行的值按编辑后的内容保存；未作修改就 **Save** 不会产生待保存的
编辑。如果文本列中的文本不再有效，第一次 **Save** 会显示警告，第二次按输入原样保存；
JSON 列则拒绝保存。

**Copy** 把编辑器中显示的文本（包括未保存的修改）原样复制到剪贴板，**Copy compact**
则复制紧凑形式。拖动编辑器的右边缘、下边缘或右下角可调整大小，也可以用关闭按钮旁边的
按钮或双击标题栏将其最大化。编辑器始终位于其所在的面板之内，因此无论大小如何、值有多长，
标题栏和按钮都保持可见。大小会在打开下一个值时保留；最大化按钮前面的 **Reset size**
按钮会把编辑器恢复为默认大小，并清除记住的大小。

| 按键 | 操作 |
|------|------|
| `Ctrl+s`（`Cmd+s`） | 保存 |
| `Ctrl+Shift+k` / `Ctrl+Shift+h` | 复制 / 紧凑复制（macOS 上为 `Cmd`） |
| `Ctrl+Shift+u` / `Ctrl+Shift+j` | 格式化 / 紧凑 |
| `Ctrl+Shift+Enter` | 最大化或恢复编辑器 |
| `Ctrl+Shift+Backspace` | 将编辑器恢复为默认大小 |

`Ctrl+c`（`Cmd+c`）仍然复制选中的文本。

### 保存前查看更改

编辑栏中保存和还原旁边的 **查看**，或 `Ctrl+Alt+S`（macOS 上为 `Cmd+Alt+S`），会按执行顺序（删除、新行、编辑过的行）显示保存将为该表未保存的更改执行的语句。这些语句由保存本身构建并由连接的驱动生成，因此就是数据库收到的内容，SQL 表达式不加引号。值以字面量写入语句；MySQL、MariaDB、PostgreSQL、SQLite 和 SQL Server 驱动不发送绑定参数。无法保存的更改（缺少主键的行）会显示为说明原因的注释。

在查看窗口中，**保存**（或 `Enter`）会执行这些语句，不再单独确认删除；**复制 SQL** 把它们作为脚本复制；**取消**（或 `Escape`）关闭窗口并保留更改。在“设置 > 通用 > 数据网格”中打开 **保存前查看更改** 后，表格网格的每次保存都会先打开查看窗口。

### 生成的 ID

可以给单元格写入由 DBFlux 生成、作为普通值写入的新标识符，因此适用于所有数据库：**UUID v4**（随机）、**UUID v7**（按时间排序）、**KSUID**（27 个字符，按秒排序）和 **ULID**（26 个字符，按毫秒排序）。

- 单元格菜单的 **设置值** 子菜单中，列能存储的每种类型各有一项。在更大选区中的单元格上，每个选中的单元格都会得到自己的新值，而不是副本，一次撤销即可全部撤回。
- 对看起来像标识符的列（`uuid` 类型、主键、长度适合某种类型的文本列，或 `user_id` 这样的名称），内联编辑器下方的列表会先列出这些类型（UUID 在最上面），`Down` / `Up` 会把新值写入编辑器。在多单元格选区上提交时，每个单元格同样得到自己的值。
- 单元格编辑器对话框中每种类型各有一个 **生成 …** 按钮。

`uuid` 或 `uniqueidentifier` 列接收带连字符的 UUID。文本列接收适合其声明长度的类型：`char(36)` 接收 UUID，`char(27)` 接收 KSUID，`varchar(30)` 接收 KSUID 或 ULID，长度未知的列四种都可以。MySQL 的 `binary(16)` 等二进制列不提供生成的 ID，因为网格写入的是文本，而这类列需要 16 个原始字节；这时请改为把单元格设为 `UNHEX(REPLACE(UUID(), '-', ''))` 表达式（参见[单元格中的 SQL 表达式](#单元格中的-sql-表达式)）。

### 结果何时可编辑

普通的表浏览在表有主键时可编辑。由**构建器**（SELECT 模式）产生的结果同样可编辑，但前提是该结果可证明绑定到单一表：结果与唯一的底层表 1:1 映射，且该表的每个主键列都以原始名称被投影出来。此后，编辑和删除会依据投影出的主键值构造 `WHERE`。

允许 JOIN：来自源表的列可编辑，被连接的列则为只读。

构建器结果在以下任一情况成立时会回退为**只读**，并在工具栏给出原因提示：

- 查询使用了聚合，或使用了 `GROUP BY` / `HAVING`。
- 投影是跨 JOIN 的通配符。
- 某个主键列缺失，或以别名形式被投影。
- 表的键尚未从 Schema 缓存加载完成（键加载完成后，网格会自动升级为可编辑）。

在编辑器中手写的自由 SQL 始终保持只读；内联编辑只适用于普通表浏览和构建器生成的 SELECT。

### 单元格中的 SQL 表达式

单元格通常保存字面量：输入的内容会作为带引号的值保存，因此输入 `now()` 会保存文本
`now()`。要保存由数据库求值的 SQL 表达式（`now()`、`gen_random_uuid()`），需要显式将
单元格标记为表达式。文本不会被自动识别为表达式。

- 单元格菜单中的 **设置值** 会打开子菜单，包含 **列默认值**（列没有默认值时禁用并
  说明原因）、连接的方言为该列类型提供的值、**NULL** 以及 **表达式…**。
- 在行内编辑器中，`Ctrl+Shift+I` 在字面量和表达式模式之间切换；没有打开编辑器时，
  会以表达式模式打开。表达式模式下编辑器显示 `ƒx` 标记，并在单元格下方列出该类型的值；
  `上` / `下` 将其放入输入框，`Enter` 保存。
- **设为默认值**（`Ctrl+Shift+0`）会暂存该列的默认表达式。

表达式单元格以强调色的 `ƒx` 显示，复制时复制的是表达式文本。写入表达式的保存会先要求确认，
因为表达式会按原样放入语句，而不是作为值绑定。拒绝则不保存该表达式，其编辑保持暂存状态。
批量保存时，它之前的行已经写入，之后的行不会写入。只有 SQL 表支持表达式，文档网格不支持。

### 聚合结果

当结果来自分组（`GROUP BY`）查询时，各行显示聚合后的输出，编辑功能被禁用 — 添加行、删除行、编辑单元格和检查行都不可用，并给出解释性提示。分页按分组后的行数计算（而不是底层行数），因此总页数是准确的。聚合列保持正确的列类型，因此仍能正常绘制图表。

## 复制为 CSV 或 JSON

表格结果的上下文菜单中，**复制** 下方的 **复制为 ▸** 子菜单以 **CSV** 和 **JSON** 开头。它们通过与
**将已加载行复制到剪贴板** 相同的导出器复制选区，无论是一个范围还是用 `Ctrl`+单击选取的
多个范围：CSV 以列名标题行开头，JSON 是每行一个以列名为键的对象组成的数组，数字、布尔值和
`null` 保持原样。选区覆盖的所有行和列都会包含在内；该区域内但未选中的单元格在 CSV 中为空，
在 JSON 中为 `null`。复制内容与网格显示的一致：未保存的编辑按新值复制，尚未保存的新增行按其位置复制。
在 JSON 中，同名的列（连接中的 `a.id` 和 `b.id`）共用一个键，取最后一列的值。普通的 **复制**（`Ctrl+c`）复制制表符分隔文本，同样包含未保存的编辑和新增行；在 设置 → 常规 → 数据网格 中打开
**复制时包含列名** 后，文本以一行所复制列的列名开头，否则不带标题。
`Ctrl+Alt+c`（macOS 上为 `Cmd+Alt+c`）可用键盘执行 **复制为 JSON**，菜单在该项旁显示此快捷键。

其下方子菜单还有三个提取项：

- **复制为 SQL IN 列表**：把一列中选中的值复制为可用于 `WHERE ... IN` 的列表，例如 `('a', 'O''Brien')` 或 `(1, 2, 3)`，按连接驱动书写字面量的方式加引号（没有连接的结果使用 ANSI 引号）。多次选中的值只列一次，`NULL` 会被省略，因为 `IN (NULL)` 不匹配任何行；只选中 NULL 时不复制任何内容并给出提示。选中多列时使用最左边的一列。集合的菜单不提供此项。
- **复制为 INSERT 语句**：在表中为每个选中的行复制一条包含所选列的 `INSERT`，由与 **复制为查询** 相同的驱动生成器生成。即使所选区域内的某个单元格本身未选中，每行也使用自己在这些列中的值；含有驱动无法写入的值的行会被省略。分组后的行和查询构建器的连接结果不提供此项，因为其中的列并不都属于该表。
- **复制为 Markdown 表格**：把与“复制为 CSV”相同的行和列复制为带标题行的 Markdown 表格；`NULL` 和未选中的单元格为空，字节写为 `\x` 十六进制，数组和文档写为 JSON，值中的 `|`、`&`、`<` 和换行会被转义。

这三项与复制为 CSV 一样，复制网格中显示的内容：未保存的编辑按新值复制，在网格中添加但尚未保存的行按其位置复制。

## 复制为查询

**复制为 ▸** 子菜单的最后是把行复制为查询（INSERT、UPDATE 或 DELETE，位于标明连接语言的标题下），文档视图的菜单仍把它作为单独的子菜单。它使用驱动自身的查询生成器，根据选中的行生成驱动专属的变更语句（对于非 SQL 驱动则是信封）。

## 导出

在结果面板中按 `Ctrl+e`（`Cmd+e`），或从命令面板执行 **导出结果**。可用格式取决于结果形态，包括：

- **CSV**
- **JSON（美化）** 与 **JSON（紧凑）**
- **文本**
- **二进制**（用于二进制形态的结果）

菜单顶部选择导出哪些内容，下方 **保存为文件** 和 **复制到剪贴板** 中的格式都遵循这一选择：

- **行**：**已选** 与复制为 CSV 一样，按网格显示写入含有选中单元格的行（包括未保存的编辑和新增行），**已加载** 写入网格当前持有的行（对表而言就是当前页），**全部** 写入表或集合的所有行（见下文；仅在网格能逐页重新读取时提供）。在选中单元格之前，**已选** 处于禁用状态，原因显示在该行下方。
- **列**：默认的 **可见** 按网格显示的顺序写入显示的列，因此隐藏的列会被略去，移动或固定的列保持原位。**全部** 按结果顺序写入所有列，包括隐藏的列。**已选** 按屏幕顺序写入含有选中单元格的可见列。已选的行与已选的列一起使用时，写入选中范围内的单元格及其值；用 `Ctrl`+单击选择多个范围时，写入这些范围覆盖的所有行和列。
- 默认开启的 **包含标题行（列名）** 和 **分隔符**（逗号、分号或制表符）适用于从此菜单保存或复制的 CSV，以及以 CSV 导出所有行。上下文菜单中的“复制为 CSV”不受影响。
- 默认关闭的 **防止电子表格公式执行** 会在从此菜单保存或复制的 CSV 以及以 CSV 导出所有行中，为以 `=`、`+`、`-`、`@`、制表符或回车开头的文本单元格和列名加上前导 `'`。电子表格打开文件时会把这样的单元格作为公式执行，而服务器上的数据可能故意带有这样的单元格，例如 `=HYPERLINK("https://example.com/?"&A1)`。开启后，电子表格会将其显示为文本；数字不变。如果文件由其他程序读取，请保持关闭，否则程序会看到 `'`。多表导出文件夹（导出数据）从不改变其中的值。对于复制和复制为 CSV，请使用“设置 > 通用 > 数据网格”中的 **防止复制的单元格作为电子表格公式执行**。

选项上方的标题说明各格式会写入什么，例如“导出已选的 12 行，4 列”；保存或复制后的提示也会给出相同的行和列，以及路径或字节数。菜单打开时位于第一个格式上，因此 `Ctrl+e` `Enter` 仍会立即保存。按 `k` 或 `Up` 移到选项；在选项行上按 `Enter`、`Right` 或 `l` 会切换到下一个适用的值，或勾选标题行复选框；单击某个值会直接选中它。你的选择对所有网格生效（而非按表区分），重启后依然保留。

将 **行** 设为 **全部** 时，菜单提供 **将所有行导出到文件**，格式为 CSV、JSON（每行一个对象的数组）或 JSON Lines（每行一个对象，`.jsonl`），也可以导出为便于阅读和分享的 HTML 表格、Markdown 表格或 XML。它会按网格当前的筛选、排序和列选择逐页重新读取整张表或整个集合，写入 **列** 选项选中的列，并以流式方式写入你选择的单个文件，因此数据无需全部载入内存。通过查询构建器或关系筛选显示的表会用同一查询读取，从该查询的偏移量开始，设置了上限时在上限处停止。导出作为任务在任务面板中运行，任务面板会显示进度并可取消；提示会说明总行数和路径。

HTML、Markdown 和 XML 文件用于阅读，不能导入：导入包含这类文件的文件夹时，导入会在该表处停止：该表失败并提示其格式无法导入，之后的表不会再尝试导入。XML 为每行写一个 `<row>`，为每列写一个 `<field name="...">`，NULL 用 `null="true"` 标记，以区别于空值。

导出向导（侧边栏中的 **Export Table…**）会把每张选中的表写入新文件夹中各自的文件，并附带一个 `manifest.json`。其 Format 步骤只显示该格式用到的选项，隐藏其余选项：

- **分隔符**（仅 CSV）：逗号、分号、制表符或竖线。
- **编码**（仅 CSV）：UTF-8、带 BOM 的 UTF-8、UTF-16LE（带 BOM）或 Windows-1252。Windows-1252 无法表示的字符不会被替换，而是让导出以指明该字符的错误中止。
- **NULL 文本**（CSV、HTML 和 Markdown）：为 NULL 写入的文本，默认为空。JSON 和 JSON Lines 始终写入 `null`，XML 用 `null="true"` 标记 NULL。文本与非空 NULL 文本相同的值在导入时会被读成 NULL，因此导出会以指明该值和列的错误中止；请选择其他 NULL 文本。使用默认的空 NULL 文本时，空字符串和 NULL 的写法相同，因此导入 CSV 时两者都会读回为 NULL；如需保留空字符串，请设置非空的 NULL 文本，例如 `\N`。
- **日期**（除 SQL 外的所有格式）：RFC 3339（默认）、UTC 的 `YYYY-MM-DD HH:MM:SS`，或 epoch 秒（JSON 和 JSON Lines 将其写为数字）。日期在前两种格式下写为 `YYYY-MM-DD`，在 epoch 下写为当天午夜（UTC）；时间在 `YYYY-MM-DD HH:MM:SS` 下写为 `HH:MM:SS`，在 epoch 下写为自午夜起的秒数。
- **每条 INSERT 的行数**（仅 SQL）：每条 `INSERT` 语句包含的行数，默认 500，最小为 1。限制每条语句行数的驱动程序（例如限制为 1000 的 SQL Server）会以其上限为准。

只有当源连接的驱动程序能够生成批量 `INSERT` 语句时，导出向导才会提供 SQL。它为每张表写出一个 `<架构>.<表>.sql` 文件，内容是该连接方言下的 `INSERT` 语句：每条语句包含一批行，按方言的写法给出表名，并以 `;` 结尾。脚本用于在空表副本中重放；执行两次会因唯一键冲突而失败，或使行重复。PostgreSQL 的 `GENERATED ALWAYS AS IDENTITY` 列会带上 `OVERRIDING SYSTEM VALUE` 写出，带有 `IDENTITY` 列的 SQL Server 表会被 `SET IDENTITY_INSERT ... ON;` 和 `OFF;` 包住，因此原始 id 得以保留。对于 PostgreSQL 表，脚本会在该表最后一条语句之后，把每个 IDENTITY 列和 serial 列的序列移过导出的值：递增序列移到最大值，递减序列移到最小值（`setval`），因此重放后按默认值插入不会重复使用已有的 id；SQL Server 在插入显式值时会自行推进 IDENTITY 种子。由数据库计算的列（PostgreSQL 和 MySQL/MariaDB 生成列、SQL Server 计算列、`rowversion` 列和时态表的时间段列 `GENERATED ALWAYS AS ROW START/END`）不会写入语句，重放时由数据库重新计算。没有行的表会写出空文件。NULL 和日期的写法由方言决定，因此 NULL 文本、分隔符、编码和日期选项不适用，并会被隐藏。SQL 文件暂不能导入：导入包含它的文件夹时，该表会失败并提示其格式无法导入。**将所有行导出到文件** 不提供 SQL。

当源连接无法写出 SQL 时，格式步骤不会列出它，并在格式选择器下说明原因：其驱动无法生成 `INSERT` 语句，请改为导出 CSV 或 JSON。每个使“继续”不可用的状态都会说明原因：页脚指明要修正的内容（**每条 INSERT 的行数**、**分块大小**、文件夹，或为空的表选择），无效字段会显示危险色边框、警示图标和提示。运行结束后，对话框为每张表列出一行结果。因失败而未被运行到的表会注明这一点，失败的运行会说明下一步该做什么：已写入的文件保留在文件夹中，失败的运行不会写入 `manifest.json`，因此无法将整个文件夹导入，但每个已完成的 CSV 或 JSON 文件仍可通过“选择文件…”导入。

默认值写出的内容与早期版本完全一致。清单会记录塑造了文件的选项，因此导入该文件夹时会以同样的方式读取；没有这些选项的清单表示使用默认值。**将所有行导出到文件** 始终使用默认值。

以 JSON 或 JSON Lines 导出文档集合时，每个文档按原样写入，每行一个对象，包含其全部字段。以 CSV、HTML、Markdown 或 XML 导出时，按网格为第一页显示的列（包括已展开的对象）写入。同一集合中的文档不必拥有相同的字段，因此在这些格式的文件中，后续页面才首次出现的字段由于表头已写入而没有对应的列；此时导出会在警告中列出这些字段。

查询结果只提供已加载的行，因为导出全部行需要重新执行查询。最近邻搜索也是如此：它返回固定数量的最近行，网格已持有全部这些行。

## 导入文件

导入向导也可以读取单个文件。在第一步中点击文件夹选择器旁的**选择文件…**，选取 `.csv`、
`.json`、`.jsonl`、`.xml` 或电子表格（`.xlsx`、`.xlsm`、`.xls`、`.ods`）文件；不提供 HTML 和 Markdown 文件，SQL 连接上的 `.sql` 文件则作为脚本运行（参见[运行 SQL 脚本](#运行-sql-脚本)）。列取自 CSV 的标题行、前
100 条 JSON 记录的键，前 100 个 XML 行中 `<field>` 元素的 `name`（按首次出现的顺序列出所有出现过的键），或电子表格工作表的第 1 行。若某个键在这些行之后才首次出现，导入会中止并报错，指明该键及其所在行。嵌套的对象或数组按 JSON 文本导入。

目标表默认为去掉扩展名的文件名；输入其他名称并点击**使用该表**（或按 Enter）即可导入到已有的表。
列映射和表模式（创建、已有、重建、清空、跳过）与文件夹导入相同。文件不带列类型，因此写入已有表的值
按该表的列类型读取，新表则为每个字段创建文本列（`TEXT`，或引擎自己的宽文本类型，如 SQL Server 的 `NVARCHAR(MAX)` 或 MySQL 的 `LONGTEXT`），因此值以文本形式存储。

CSV 文件提供与导出向导相同的分隔符、编码和表示 NULL 的文本选项；JSON、JSON Lines 和 XML 没有选项。XML 文件必须是导出所写的形状：
根元素 `<rows>` 包含 `<row>` 元素，每行为每一列有一个 `<field name="...">文本</field>`。写成
`<field name="..." null="true"/>` 的字段为 NULL，空的 `<field>` 为空字符串，`&#10;` 等字符引用会被解码。
其他 XML 形状会被拒绝，并提示所期望的形状。
更改分隔符或编码会重新读取文件。写入任何内容之前会先完整读取一遍文件，因此格式错误的行或记录会使
导入中止，且不改动目标。

电子表格每次导入一个工作表。配置步骤会多出一个**工作表**下拉框，列出工作簿中可见的工作表，并从第一个开始；隐藏的工作表和图表工作表不会列出，选择其他工作表会立即重新读取文件并重建列映射。只有一个可见工作表的工作簿会显示该工作表且下拉框不可用，并说明无需选择。工作表的第 1 行是表头，因此每一列都需要唯一且非空的名称；电子表格没有分隔符、编码或 NULL 选项。数字、布尔值、日期、日期时间和文本按相应类型读取，空单元格为 NULL，公式按文件中最后保存的结果读取。使用 1904 日期系统的工作簿也能正确读取日期，但其中的时间会作为 1904-01-01 的时间戳而不是时间读入。整个工作表会读入内存，因此超过 10,000,000 个单元格（行 × 列，从 A1 起算）的工作表会被拒绝。无法导入的工作表会让文件保持选中并停留在配置步骤，显示一个说明下一步该做什么的危险色块：工作表为空、第 1 行有空名称或重复名称（色块会列出相关列）、某个单元格的值为错误值，如 `#DIV/0!`（色块会指出工作表、行和列；第 1 行的单元格同样适用，因此错误值不会被当作列名），或工作表超过上限（将其导出为 CSV 后导入该 CSV，或选择较小的工作表）。每种情况都可通过选择其他工作表摆脱；如果工作簿没有其他可见工作表，色块会改为提示在电子表格应用中修正该工作表、保存后重新选择文件。页脚会说明“继续”不可用的原因。

导入对话框使用与导出向导相同的顶部步骤条和页脚：前两步为“取消”，确认步骤为“返回”和“取消”，“继续”是主按钮。无法读取的文件或文件夹会显示一个危险色块，给出错误和下一步该做什么。表头无法解码的 CSV 会停留在配置步骤，换一个分隔符或编码即可重新读取；损坏的 JSON 会停留在第一步，直到选择另一个文件；目标表查找失败会说明这一点，并通过“使用该表”重试。页脚会说明“继续”不可用的原因（正在读取文件，或文件无法读取）。JSON 和 JSON Lines 会显示一行说明它们没有选项，在无法清空表的连接上，还会有一行解释为何不列出 Truncate。在文本字段中，`Escape` 离开该字段并把按键交还给对话框；再按一次 `Escape` 关闭向导。运行结束后，每张表一行列出其结果，失败的运行会说明下一步该做什么。

### 运行 SQL 脚本

在查询语言为 SQL 的连接上，**选择文件…**也会提供 `.sql` 文件；其他连接永远看不到它们，如果
`.sql` 文件仍然被选中，会被拒绝，并提示该连接不是 SQL。选中后，会在同一个对话框中打开**运行 SQL
脚本**流程。脚本按 UTF-8 读取，并用编辑器自己的拆分器拆成语句，因此引号、注释和美元引用的正文都会被
正确处理，也没有分隔符或编码选项。超过 100 MB 的脚本、不是 UTF-8 或无法读取的文件，以及没有语句的
脚本，都会停留在第一步，并说明原因和下一步该怎么做。只有命令行客户端才能运行的内容也是如此：
`DELIMITER` 行或 `GO` 批分隔符、周围没有客户端分隔符且语句以 `;` 结尾的例程体（存储过程、函数或触发器）、
`COPY … FROM stdin` 数据块，以及 `\connect` 这类 psql 反斜杠元命令，还有关闭 autocommit（`SET autocommit = 0`）或开启隐式事务的语句（会让连接停留在手动提交模式）。它们都会在运行任何内容之前被拒绝，
并给出行号和下一步：用数据库自带的命令行客户端运行脚本，或改写脚本（`COPY … FROM stdin` 数据块或 psql 元命令请使用 psql：删除 `\connect` 行会让其余语句在此连接上运行，而这可能不是它所选择的数据库）。超过 100 MB 的脚本也可以拆分为较小的文件，但每个文件都是单独运行的：后面的文件失败时无法撤销前面的文件。

**配置**步骤显示语句数量和大小、每个分类中的语句数量（编辑器和审计查看器使用的分类，包括管理），以及
前六条语句及其分类；没有 `WHERE` 的 `DELETE` 或 `UPDATE` 会被标记。更改序列的语句（`setval`、`nextval`、
`ALTER SEQUENCE`）按写入统计，因此只读连接会拒绝它们。它有两个选项：

- **出错时**：**遇到第一个错误时停止**（默认）或**出错后继续**；后者会运行所有语句，并列出失败的语句。
- **在一个事务中运行**：连接支持事务时默认开启。如果某条语句失败，事务中所做的更改会被回滚，在最后一条
  语句成功之前不会保存任何内容。选择**出错后继续**时它会关闭并说明原因（在某些引擎上失败的语句会中止
  事务）；在不支持事务的连接上则不提供，并说明原因。自行管理事务的脚本（`BEGIN`、`START TRANSACTION`、`COMMIT`、
  `END`、`ROLLBACK`、`SAVEPOINT`、`RELEASE`、`SET autocommit`）也会关闭它，并指出语句及其行号：脚本按原样运行，
  其中的 `COMMIT` 会保存它之前的更改。脚本打开却从未结束的事务会在脚本结束时被回滚，对话框会说明这一点：请在末尾添加
  `COMMIT` 以保存其更改。如果该回滚失败，对话框会提示可能仍有事务处于打开状态，需要断开并重新连接。含有控制事务的版本条件注释的脚本会被拒绝，因为它是否运行取决于服务器。在事务之外使用 `SAVEPOINT` 的脚本会在结束时被执行一次预防性的 `ROLLBACK`，以防有事务被遗留为打开状态；对话框会说明这一点，数据库已经提交的更改会保留。

在自行提交架构语句的连接上（MySQL 和 MariaDB），`CREATE`、`ALTER` 和 `DROP` 在运行时就会保存，并一并保存
它们之前的所有语句，因此回滚只能撤销最后一条此类语句之后所做的更改。序列的更改（`setval`、`nextval`）
永远不会被回滚撤销。按配置文件设置为只读的连接会拒绝更改数据、结构或权限的脚本，说明有多少条语句会这样做，并
让**继续**保持关闭；只读取数据的脚本可以运行。

无论内容如何，每个脚本都要经过**确认**。没有破坏性语句的脚本会显示每个分类中的语句数量，并提供**运行
脚本**。含有破坏性语句的脚本会显示危险提示块，按编辑器的危险查询类型统计数量，列出前三条及其在文件中的
序号，并提供**是，运行脚本**。**返回**会回到配置步骤。

**运行中**步骤显示“正在运行第 N / M 条语句”、当前语句和任务面板中的一项。**取消运行**会在当前语句结束后
停止，并请驱动程序中断它。在一个事务中，更改随后会被回滚；没有事务时，已运行的语句会保留。底部会在你按下
之前说明是哪一种情况。

脚本在配置文件的连接上运行，因此它的语句和事务与从该配置文件发起的其他操作共享同一个连接。运行脚本之前，请让该连接上的其他工作（编辑器、网格、另一次导入）先完成，并且在运行结束之前不要在其上启动新的工作：在脚本事务中途运行的查询可能会随它一起被回滚或保存。在提供独立会话的驱动程序上，脚本会在自己的会话中运行，其他工作无法加入脚本的事务，**取消运行**也只会停止脚本。其他会话仍然可以锁定或更改脚本使用的对象，因此脚本可能需要等待它或与它冲突。在没有独立会话的连接上，文件夹或文件导入也有同样的特性。

**完成**步骤说明发生了什么。停止的运行会指出语句（序号、行号和文本），显示数据库的错误，说明之前的语句怎么
样了以及下一步该做什么；出错后继续的运行会列出每条失败的语句。没有事务时，建议是先核对之前的语句已经做出的更改，并在运行其余语句之前保留
或恢复脚本需要的会话设置（如 `SET search_path`）；出错后继续的运行也是同样的建议。如果提交或回滚本身失败，对话框会说明结果不明确，
并提示在执行其他操作之前先检查数据库的状态。每次失败还会以带有**在审计中查看**的提示形式报告一次，每次运行
会记录一个 `Query` 审计事件（每条失败的语句再加一个，最多 50 个），其中只包含语句的第一行，并按审计设置进行
脱敏。
